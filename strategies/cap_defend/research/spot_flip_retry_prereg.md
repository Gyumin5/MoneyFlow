# 사전등록 — 전환일 전부 현금 잠김을 고치는 후보 넷 (2026-10-18)

## 무엇을 묻나

2026-07-14 카나리 켜짐에 현물이 19일 늦게 들어갔다(history #72). 기제는 전환일에 건강도
필터를 통과한 코인이 0 이라 스냅샷 일곱 개가 전부 현금으로 채워졌고, 그 뒤로는 스냅샷이
자기 차례(약 31일 간격)에만 갱신되며 드리프트는 현금 대 현금이라 발화할 수 없었던 것이다.

이 자리를 고칠지 백테스트로 먼저 잰다. 라이브 코드는 이 측정에서 한 줄도 안 바꾼다.

## 팔

현물만 바꾼다. 선물·주식 팔은 전 팔에서 동일하다(합성 60/25/15 의 고정 자리).

| 이름 | 바꾸는 것 |
| --- | --- |
| 현행 | 채택 백테스트 그대로 (전환 후 5봉에 전 스냅샷 재평가 = post_flip_delay 5) |
| 라이브현행 | post_flip_delay=0 — 지금 라이브 엔진이 실제로 하는 것 |
| 가-다음봉 | 전환일이 전부 현금이면 바로 다음 봉에서 한 번만 다시 본다 |
| 나-생길때까지 | 전환일이 전부 현금이면 통과 코인이 처음 생기는 봉까지 매 봉 다시 본다 |
| 다-단기18일 | 현물 단기 모멘텀 20일 → 18일 (선물과 같게) |

가·나는 백테스트 엔진에 환경변수 FLIP_ALL_CASH_RETRY(off/next/until)로 넣었다. 기본값
off 에서 기존 동작과 바이트 단위로 같은 것을 확인하고 측정 후 되돌린다.

라이브현행 팔은 후보가 아니라 진단이다. 채택 백테스트에는 전환 후 재평가가 이미 있는데
라이브 엔진에는 없다 — 그 차이가 얼마인지 같이 적는다.

  슬리브 단독 성적은 진단으로만 적는다.

- 네 지표를 전부 적는다 — 칼마·샤프·연복리·최대낙폭.

## 채택 기준 (결과를 보기 전에 정한다)

후보가 다음을 전부 충족하면 ai-debate 로 넘기고, 하나라도 어긋나면 그 자리에서 기각한다.

1. 합성 순위 평균이 현행보다 낮다(우세). 기본 비용과 비용 5배 양쪽에서.
2. 앵커 7곳 중 5곳 이상에서 현행보다 순위가 낮다.
3. 합성 최대낙폭 평균이 현행보다 1.0pp 넘게 나빠지지 않는다.
4. 합성 칼마 평균이 현행보다 낮지 않다.

통과가 0 이면 결론은 "현행 유지" 이고 라이브를 안 바꾼다. 다만 라이브현행 팔이 현행보다
확연히 나쁘면, 그건 전략 변경이 아니라 채택 백테스트와의 어긋남이므로 따로 보고한다.

## 같이 적는 진단 (기준 아님)

- 전환 ON 인데 통과 코인이 0 이라 전부 현금이 된 사건 수.
- 그 사건마다 현금으로 잠겨 있던 봉 수 (현행 / 라이브현행 각각).
